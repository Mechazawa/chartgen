# Agent notes

## Environment
- Linux only. `scripts/install.sh` builds `.venv` (CUDA torch when `nvidia-smi` works).
- Tests: `.venv/bin/python -m tests.test_chartgen` and `.venv/bin/python -m tests.test_motifs`. There is no linter config.
- madmom 0.16.1 on PyPI does not build on Python 3.14. `scripts/install.sh` installs cython, then a pinned madmom git commit with `--no-build-isolation --no-deps`. The venv may have no pip (uv-built): use `uv pip install --python .venv/bin/python`.
- Kill background jobs by PID (`ps -eo pid,comm,args | awk '$2 ~ /python/ ...'`). `pkill -f <pattern>` also matches the shell that runs it.
- Basic Pitch amplitudes change in the last float32 bit with onnxruntime's `intra_op_num_threads`, so the events no longer match the cached ones. To run several transcriptions at once, keep the default thread count; `transcribe.transcribe` turns off thread spinning instead.

## 6-fret (GHL) part
- Lanes 0-5 are W1 W2 W3 B1 B2 B3 and 7 is open, in the same `(tick, lane, sustain)` tuples as 5-fret. The writer maps lane 5 to `.chart` note 8 (`chart.GHL_NOTE`).
- `chartgen/ghl.py` holds the feature functions, `TimingNet` (Expert note times), `ShapeNet` (Expert shapes), `ReduceNet` (Hard/Medium/Easy keep + shape) and `chart_tiers()`. Weights, the timing threshold and per-tier allowed shapes ship in `chartgen/ghl_model.pt`.
- The 6-fret part is independent of the 5-fret chart. `TimingNet` scores every 1/12 beat of the beat grid (16ths plus 8th and 16th triplets) from the transcription, nearby onsets and the mix's onset envelope; `pick_slots` keeps slots above the threshold at least `GAP_S` apart, as grid ticks. An Expert note sustains to the next note when that note is at least `SUSTAIN_GAP_S` away and the note is not open; lower tiers keep a sustain when their own next note is `TIER_SUSTAIN_BEATS` away. Each lower tier is drawn from the one above it (`nested_keep`).
- Training data are the official FreeStyleGames charts only (Guitar Hero Live on-disc and GHTV, 561 songs). Do not mix in community charts or 5-to-6 converts.
  1. `data/ghl-official/` holds the song folders: Drive rips of the on-disc set, plus `python -m tools.fetch_official_ghl` for the Encore rows with icon `ghl`/`ghtv`.
  2. `python -m tools.build_ghl_dataset data/ghl-official` runs the pipeline's listening front end (Basic Pitch on the mix and on every BS-RoFormer stem, and the beat grid) into `data/ghl-features/*.pkl`. After a change to `tempo.detect`, delete the `tempo` key or the records to detect the grid again. It needs about 35 s a song on an RTX 3060 and takes the whole GPU, so run nothing else on the GPU in parallel.
  3. `python -m tools.train_ghl data/ghl-features --sweep 16` trains the three models (16 random configurations each, best validation loss wins) and records the configuration and the held-out songs in the model file. Curves: `tensorboard --logdir data/ghl-runs --host 127.0.0.1`.
  4. `python -m tools.eval_ghl -n 10` charts held-out songs end to end and scores the 6-fret part against the official chart. It prints a chance line (official shapes shuffled over the official positions) beside every shape score, sustain precision and recall, a style panel (z against `data/ghl-eval-stats.json`, built from the training songs) and how alike repeated sections are.
- Memory: `train_ghl` holds the whole dataset (about 6 GB of RAM). Run nothing else that loads all records at the same time, or the machine runs out of memory.
- `ShapeNet` predicts chord size, row and column set separately and composes the 64 shape scores from them (`factor_weights`, picked on validation, weight size up; equal weights lose to the majority class). A direct 64-way softmax scored no better than always the majority size and row.
- Expert shapes are decoded per figure (`ghl.figure_shapes`): a figure starts where the relation head gives P(SAME) <= 0.5, and a `scipy.optimize.milp` gives each figure one shape, maximising the calibrated log probability while each shape's note count stays within 0.7x-1.1x of its quota, and neighbouring figures differ where P(SAME) <= 0.35 (without that, the repeat rate is 47-49% against the official 41%). The quota is the song's expected shape counts ** `quota_power`, rescaled within each chord size: raising the power over all shapes at once pushed singles from 54% to 64%. The MILP stops at 20 s, so a loaded machine can give slightly different charts. A per-note argmax or Viterbi puts the same few shapes everywhere (72% of 2-button chords vertical W+B pairs against the official 27%) and holds no figure. Hard and Medium use `ghl.viterbi` over the kept positions with a row-switch weight; Easy takes each position's best allowed shape.
- `train_ghl` calibrates the decode on the validation songs: ShapeNet's `temperature` (about 5) and per-shape `shape_bias` by likelihood, `quota_power` as the lowest of (1, 1.5, 2, 2.5, 3) whose mean style entropy z is at most 1 (power 1 gives +1.6 and flags 57% of held-out songs; each step up raises the histogram distance), and the Hard and Medium switch weights so each tier, reduced from the decoded Expert shapes, switches row as often as the official tier (Hard 24%). `python -m tools.train_ghl data/ghl-features --recalibrate chartgen/ghl_model.pt` redoes only these validation steps on saved networks, in about 15 minutes. The per-shape bias absorbs the old per-size-and-row mix bias, and the MILP has no Expert switch weight (a pairwise term would not be linear). Known gap: row-adjacent pairs (W+W, B+B) are 4-8% of 2-button chords against the official 25%.
- `tools/eval_ghl.py -n 0` scores every held-out song key (54); `-n 10` takes the first ten by name, which includes one live song at 157% of the official note count, so it reads high on density.
- `tempo.detect` tracks beats with madmom's RNN + DBN tracker and does not shift them (madmom's lag is -1.5 ms). `_logits` runs madmom's eight BLSTMs stacked: about 3 s a song on the CPU against 17 s in madmom, with the same beats. librosa's onset envelope still peaks about 30 ms late, so every lookup of it against the beat grid subtracts `ONSET_LAG_S`. There is no automatic tempo-octave rule: a fixed BPM range made madmom's octave worse on the official charts (69-258 BPM).
- `tempo.detect` also sets `TempoMap.downbeat_phase` (index of the first downbeat in `beat_times`, one 4/4 phase per song) from madmom's downbeat BLSTMs, about 4 s more a song on the CPU. ReduceNet's bar columns use it at run time and the official `time_signature` bar lines in training; without a phase they are zero, because bars counted from tick 0 score worse than no bar columns.
- More official charts barely help the shapes: a learning curve on 25/50/100% of the songs scores the same chord size and row.
- The chart-to-audio offset of an official song is its `song.ini` `delay`. Onset matching alone locks onto a beat-multiple on periodic music.
- Official ladder facts (from the official charts): every lower-tier note sits on an Expert tick, Easy uses only W1/W2/W3, W1+W2 and W2+W3, and Medium has no 3-button chords.
